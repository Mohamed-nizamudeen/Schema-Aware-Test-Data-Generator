# AI Usage Note

## Schema-Aware Test Data Generator
### Infinite Computer Solutions — Tech Round AI Prototype Challenge

---

## What AI Helped With

This project was developed as a 1 day prototype. AI assistance was used for the following:

1. **Project Architecture Design** — AI helped outline the modular folder structure (`src/`, `tests/`, `docs/`, `sample_data/`) and suggested separating concerns into distinct modules (`ddl_parser`, `agent`, `data_generator`, `validators`, `exporters`).

2. **DDL Parser Logic** — AI helped design the regex patterns for parsing `CREATE TABLE` statements, especially handling edge cases like `DECIMAL(10,2)` commas inside parentheses and inline vs. table-level constraints.

3. **Agent Loop Design** — AI proposed the 6-step OBSERVE → THINK → PLAN → ACT → VALIDATE → REPORT loop pattern as a clean way to demonstrate an "agent capability" using pure rule-based logic without any paid API.

4. **Column Semantic Classification** — AI suggested the keyword-matching dictionary (e.g., `email` → `fake.email()`, `created_at` → `fake.date_time_this_year()`) as a practical substitute for an LLM inference call.

5. **Streamlit UI Layout** — AI helped design the tab-based UI with gradient headers, metric cards, and agent log styling using custom CSS.

6. **Test Case Structure** — AI helped write comprehensive `pytest` test cases covering parser correctness, topological ordering, data generation, and FK validation.

7. **Documentation** — AI assisted in drafting the README, this AI usage note, and the architecture documentation.

8. **Frontend Integration** — AI helped refactor the backend from Streamlit to FastAPI and wire up the modern React frontend with Zustand state management and Fetch API.

---

## What AI Got Wrong (and How We Fixed It)

| Issue | What happened | Fix applied |
|-------|---------------|-------------|
| Regex for `DECIMAL(10,2)` | Initial regex split on the comma inside parentheses, breaking the column parser | Wrote a custom `split_table_body()` function that tracks parenthesis depth |
| FK pattern matching | First version missed backtick-quoted table names common in MySQL exports | Added optional backtick stripping in the FK regex pattern |
| Topological sort edge direction | AI initially reversed parent/child direction in the graph, generating children before parents | Corrected the `in_degree` calculation to track "tables this table depends on" |
| Export path on Windows | `os.path.join` with `/dev/null` in `get_report_bytes` failed on Windows | Added OS detection and fallback to `NUL` for Windows |

## Best Prompts Used

1. *"Design a modular Python project structure for a DDL-based test data generator that respects FK relationships, supports an agent loop, and can export CSV + SQL."*

2. *"Write a pure Python regex-based parser for SQL CREATE TABLE DDL that extracts column names, types, PRIMARY KEY, FOREIGN KEY, NOT NULL, and UNIQUE constraints without using any external SQL library."*

3. *"Implement a Kahn's algorithm topological sort in Python that detects circular dependencies in a FK graph and raises a custom exception."*

4. *"Design a 6-step agent loop (OBSERVE, THINK, PLAN, ACT, VALIDATE, REPORT) for a data generation tool that logs each step and can be displayed in a Streamlit terminal-style panel."*

5. *"Write pytest unit tests for a FK validator that should detect when a child row references a parent ID that doesn't exist."*

## How AI Was Used Responsibly

- **Verification:** Every code block generated by AI was read, understood, and tested manually before inclusion.
- **No Blind Acceptance:** When AI output was incorrect (see above table), the issue was diagnosed and fixed by hand.
- **Transparency:** This note documents what AI contributed and where it failed.
- **No Paid APIs:** All AI tooling used was either a local model or a free-tier assistant. The project itself uses zero paid APIs at runtime.
- **Attribution:** The core logic (regex patterns, topological sort, agent loop, Faker integration) was validated against Python documentation and online references.

---

## How the Team Verified the Output

1. **Manual Test Runs:** The app was run with the e-commerce and college schemas, and outputs were manually inspected for correctness.
2. **pytest Suite:** All 4 test files were executed and all tests passed before final submission.
3. **FK Cross-Check:** Generated CSV files were imported into DB Browser for SQLite to verify foreign key consistency.
4. **Code Review:** Each module was reviewed for readability, comments, and error handling before commit.
